# 拡張性の検討メモ（未実装）

同一チャンピオンに対する複数ガイド（別ユーザ、別ロール）を管理する方法の検討です。実装はしていません。

## 現状

- `data/matchups/` のファイルを `scripts/build-local-data.js` で結合し、`data/matchups.json` と `data/guide-data.js` を生成する。
- キーはチャンピオンIDまたは汎用対面のカテゴリ組み合わせID。1キーにつき1ガイド。
- `app.js` はキーを `matchups[championId]` で直接引く。同一チャンピオンの複数ガイドには対応していない。

## 要件

- 別ユーザによる同一チャンピオンへの対策を管理したい。
- 異なるロール（トップFiora、ミッドFioraなど）の対策を管理したい。

## 案A: キーに軸を足す

- キーを `Aatrox@top`、`Aatrox@mid@userA` のように拡張する。
- 保存形式とビルドはほぼそのまま。1ファイル1キーも維持できる。
- 欠点: キーを文字列で組み立てて分解する必要がある。一覧が分かりにくくなりやすい。

## 案B: ガイドに属性を持たせる（推奨）

- 各ガイドに `role`（自分のロール）と `author` を追加する。
- ファイルをロール別に置く。例: `data/matchups/top/Aatrox.json`、`data/matchups/mid/Aatrox.json`
- 結合JSONはロール別にする。例: `{ "top": { "Aatrox": {...} }, "mid": {...} }`
- 画面にロール切替を追加する。

### 別ユーザの対策

- `author` 別に `data/matchups/<role>/<author>/Aatrox.json` と置く。
- 画面ではロールと作者のセレクタで切り替える。
- 作者が増える場合は、PRで追加を受け付ける運用が必要。

## 決めておくこと

1. 同じ相手への対策を並べて比較したいか、切り替えるだけでよいか。
2. 汎用対面（`ap-assassin` など）もロール別にするか。
3. 他のユーザーはPRで貢献するのか、各自のローカルで使うのか。
4. 既存データの移行先を `top` にするか。

## 案Bを採用する場合の作業

1. 既存の2件を `data/matchups/top/` に移行する。
2. ビルドスクリプトをロール別の結合に変更する。
3. `app.js` の読み込みと一覧・詳細表示にロール切替を追加する。
4. エディタに `role`（と必要なら `author`）の入力を追加する。
5. `README.md` と `docs/publishing-guide.md` を更新する。
