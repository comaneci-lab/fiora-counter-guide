# Fiora Counter Guide

Fiora向けのトップレーン対面ガイドです。試合中のゲームデータは取得せず、GitHub Pagesで静的に公開することを想定しています。

## ローカルで確認・編集する

プロジェクトのルートで静的HTTPサーバーを起動します。

```powershell
python -m http.server 8000
```

- 閲覧画面: `http://localhost:8000/`
- ローカル編集画面: `http://localhost:8000/editor.html`

編集画面で作成・検証・プレビュー・JSON書き出しを行い、書き出したデータを `data/matchups.json` に反映してからPull Requestを作成します。入力フォームはGitHub Pagesにはデプロイされません。

編集画面はData Dragonから最新バージョン、日本語チャンピオン・ルーン・アイテム・Fioraスキル・サモナースペル情報を取得します。通常の利用にはインターネット接続が必要です。「画像入りHTMLを書き出す」では画像をBase64としてHTMLに埋め込み、保存後はオフラインで開けます。画像の取得に失敗した場合はエラーを表示し、HTMLは出力しません。

## 対策データを追加する

1. `http://localhost:8000/editor.html` を開き、「チャンピオン別の対策」または「汎用チャンピオンの対策」を選び、更新日、更新時のパッチ、必要な項目を入力します。
2. 汎用チャンピオンでは、独立カテゴリを複数選ぶとその組み合わせが表示名になります（例: `AD` + `アサシン` → `ADアサシン`）。通常チャンピオンには独自カテゴリを付けません。
3. 「プレビュー」で内容を確認します。更新情報と少なくとも1つの対策項目が必要です。
4. 「JSONを書き出す」で `matchup-<champion-id-or-category-id>.json` を取得します。
5. ダウンロードしたJSONの最上位キーと値を `data/matchups.json` に追加します。同じキーがあれば、その値を新しい内容に置き換えます。汎用対面も同じファイルに追加し、独立カテゴリは `data/categories.json` で管理します。
6. 変更をコミットしてPull Requestを作成します。静的サイト自体は認証情報を持たず、公開データを直接変更しません。

フォーム内容は送信・自動保存されません。ブラウザーを閉じる前にJSONを書き出してください。

## データ形式

`data/matchups.json` にチャンピオンのData Dragon IDと汎用対面のカテゴリ組み合わせID（例: `ap-assassin`）をキーとして保存します。汎用対面には `categories` を設定し、名前は選択カテゴリから生成されます。登録済みの汎用対面だけ一覧に表示されます。データは最新の対策のみを保持し、履歴は管理しません。

```json
{
  "ChampionId": {
    "updatedAt": "2026-01-01",
    "patch": "16.1.1",
    "source": "manual",
    "macroPlan": "レーン戦終了後の動き",
    "lanePlan": "レーン戦の動き",
    "micro1": "レベル1",
    "micro2": "レベル2",
    "micro3to5": "レベル3〜5",
    "micro6": "レベル6",
    "runes": {
      "primaryStyleId": 8000,
      "primaryPerkIds": [8005, 9111, 9104, 8014],
      "secondaryStyleId": 8100,
      "secondaryPerkIds": [8126, 8135],
      "shardIds": [5008, 5008, 5011]
    },
    "summonerSpells": [[4, 12], [4, 14]],
    "skillOrder": ["Q", "W", "E", "Q", "Q", "R", "Q", "W", "Q", "W", "R", "W", "W", "E", "E", "R", "E", "E"],
    "matchupRating": "五分",
    "laneRating": "やや不利",
    "build": {
      "start": ["1055", "2003"],
      "early": ["1055", "1001"],
      "core": ["6632", "3111"],
      "options": [
        {"note": "相手の回復量が多い場合", "items": ["3078"]},
        {"note": "", "items": ["3153"]},
        {"note": "耐久力が必要な場合", "items": ["6333", "3364"]}
      ]
    }
  }
}
```

汎用対面もチャンピオン別ガイドと同じ項目を使い、カテゴリ組み合わせIDをキーにして `matchups.json` に保存します。独立カテゴリの組み合わせは `categories` に保存します。カテゴリは `AD`、`AP` とロール別に定義し、`ADアサシン` などの組み合わせ自体はカテゴリとして登録しません。汎用ガイドを登録するまでは一覧に表示されません。未記入の任意項目は省略できます。更新日とパッチバージョンは記録します。通常チャンピオンに独自カテゴリを割り当てる機能はありません。ガイドには任意で `matchupRating` と `laneRating` を設定でき、値は `有利`、`やや有利`、`五分`、`やや不利`、`不利` のいずれかです。評価はガイドのチャンピオン名の横に表示されます。

汎用対面の書き出し例です。ダウンロードしたJSONの `"ap-assassin"` オブジェクトを、`matchups.json` の他のチャンピオンと同じ階層に追加します。既存のチャンピオン項目と同じ順序で、基本情報、テキスト対策、ルーン、サモナースペル、スキルオーダー、評価、カテゴリ、ビルドを出力します。

```json
{
  "ap-assassin": {
    "updatedAt": "2026-11-26",
    "patch": "16.23.1",
    "source": "manual",
    "macroPlan": "汎用APアサシンへの対策",
    "categories": ["ap", "assassin"]
  }
}
```

上記の空欄やサンプル値を手で作る必要はありません。編集画面の「JSONを書き出す」で生成した内容を使ってください。

対面一覧には個別の対策データがあるチャンピオンと、登録済みの汎用チャンピオンのみ表示します。一覧は名前検索のみで、カテゴリ絞り込みはありません。サモナースペルはData DragonのIDを `summonerSpells` に2つずつ組にして指定します。組を複数登録するとOR条件になります（例: `[[4, 12], [4, 14]]`）。従来形式の `[4, 12]` も読み込めます。

ルーンは画像をクリックしてメインパス4つ（キーストーンを含む）、異なる段からサブパス2つ、攻撃・フレックス・防御シャード各1つを選択します。ルーンにカーソルを合わせるかフォーカスすると、Data Dragonの説明を確認できます。スキルオーダーはQWERアイコンを行、Lv1〜Lv18を列にした表で選び、基本スキルとRのレベル別上限を検証します。ビルドは `start`（スタートアイテム）、`early`（序盤アイテム）、必須の `core`（コアアイテム）の順に記録し、スタートと序盤は各6アイテムまで選択できます。コアには1つ以上必要で、コアにメモを付けられる任意の `options` 3パターンを追加できます。コアと各オプションの組み合わせはそれぞれ最大6アイテムです。従来形式のビルド配列はコアとして読み込みます。アイテムは画像から選択でき、名前検索とファイター・アサシン・メイジ・マークスマン・タンク・サポートなどのカテゴリで絞り込めます。アイテムカテゴリはData Dragonのタグを用いた独自フィルターで、複数カテゴリに表示されるアイテムがあります。チャンピオン・スキル・アイテム・ルーンの画像ファイル名はData Dragon JSONの `image.full` / `icon` から取得します。シャード画像はData Dragon JSONに対応情報がないため、シャードIDと画像名の対応を定義しています。画像付きオフラインHTMLはスキルオーダーを最上段に全幅表示し、サモナースペル・ルーン・ビルドを左、立ち回りを右に配置します。ビルド内の各カテゴリは罫線で区切られます。

アイテム候補はサモナーズリフトの通常ショップを対象とし、別モード用アイテムと同名の重複候補は表示しません。

立ち回りは `マクロ` と `ミクロ` に分け、ミクロの中に `レーン戦`、`Lv1`、`Lv2`、`Lv3〜5`、`Lv6` を記録します。

## GitHub Pages

GitHub Actionsの `Deploy static site to Pages` ワークフローを含みます。GitHubでこのフォルダーを独立リポジトリとして作成し、Settings → PagesでBuild and deploymentのSourceにGitHub Actionsを選択してください。初回push後にActionsがサイトをデプロイします。

## Data Dragon

最新のData Dragonバージョンと日本語チャンピオン一覧をページ読み込み時に取得します。Data Dragonが利用できない場合、ガイドデータは静的ファイルに残りますが、チャンピオン選択と画像は読み込まれません。
